# Протокол проверки SOLVAR v2

Среда: Linux, локальный Bun 1.3.14, TypeScript project references, Chromium headless. Только отдельные временные SQLite-БД и фиктивные контакты. На solvar.ru не выполнялись отправка заказов, платежи, нагрузочные или атакующие проверки.

## Серверный функциональный тест — PASS
`packages/web/tools/test-orders.ts`:
- анонимам недоступны заявки, заметки, счета и отправка почты;
- подписанный HttpOnly/SameSite cookie; без сессии новая заявка не принимается;
- актуальные цены, недоступные товары, согласие, honeypot, размер тела и proxy IP;
- параллельные разные requestId с формами 8…/+7…: одна активная заявка;
- параллельные разные телефоны в одном браузере: одна активная заявка;
- повтор потерянного ответа с тем же ID не создаёт новую заявку/уведомление;
- заметка сохраняется, недоступна публичному каталогу и не включается в уведомления; устаревшая версия не перезаписывает запись;
- поиск/фильтры; HTTPS allowlist для оплаты; история; закрытие/удаление; интервал повторной заявки;
- реальная SMTP-протокольная отправка на локальный fake SMTP-сервер, без реальной доставки во внешние ящики;
- Telegram и CAPTCHA имитированы; ошибки Telegram не мешают SMTP и не удаляют заявку;
- очередь сохраняет задержку, повторяет после её истечения, восстанавливает зависшую попытку, не повторяет уже отмеченное отправленным;
- CAPTCHA: отказ при ошибке/неверном action, успешный mock принимается, отсутствующие ключи выключают обязательный приём;
- отдельный процесс видит исчерпанный лимит; два независимых процесса с общей SQLite создают ровно одну активную заявку с одного телефона;
- максимальное уведомление укладывается в Telegram 4096 символов; сохраняется полный текст политики;
- быстрый flood локального order-session ограничивается HTTP 429; выключенный приём не создаёт заявку.

При разработке обнаружены и исправлены SQLITE_BUSY при конкуренции и несовместимость JOSE после обновления авторизации. Конечный прогон завершился `ALL V2 ORDER TESTS PASSED`.

## Миграция и бэкап — PASS
`tools/test-upgrade.ts`: старая схема shop_orders, существующая заявка и тестовый товар; миграция выполнена дважды; исходный JSON и каталог сохранены, новые колонки/таблицы/блокировка legacy-телефона созданы.

`tools/backup-local.ts`: SQLite VACUUM INTO; резервный файл открыт отдельно, PRAGMA quick_check = ok, таблица заказов читается. Это проверка локального snapshot, не проверка инфраструктуры резервирования рабочего хостинга.

Серверный HTML: canonical главной и начальный текст, 404 неизвестного URL, noindex админки, товары в sitemap — PASS.

## Регрессия исходного магазина — PASS
`tools/verify.ts`: 65 позиций; цены совпадают с поставляемым seed; себестоимость скрыта; анонимные изменения запрещены; вход администратора; защита удаления компонентов набора; загрузка Sharp/WebP и сохранение; создание/удаление тестового товара; публичная регистрация выключена. Упоминание Excel в console.log старого скрипта не означает сверку с отсутствующим оригинальным Excel/поставщиком.

## Сборка и отдельный production-runtime — PASS
- `tsc -b packages/web`, `npm run build:web`.
- `npm ci --dry-run --ignore-scripts` проверяет manifest/lockfile; bun.lock синхронизирован, но отдельная установка по нему не являлась путём приёмки.
- В свежей отдельной копии выполнено `npm ci --omit=dev --workspace=@template/web --include-workspace-root=false`: 147 установленных, аудит 149 пакетов, 0 известных предупреждений.
- Этот runtime запущен системным/внешним Bun с NODE_ENV=production, без dev/mobile/desktop/root PM2: health/ready/главная/товар = 200, неизвестный URL = 404, production session cookie содержит Secure.
- Общий npm audit монорепозитория: 63 (23 moderate, 39 high, 1 critical). Остаточные риски не скрыты; это не production web-only дерево.
- Предупреждение Vite о chunks >500 kB остаётся. Проверена отложенная загрузка 3D, но Lighthouse/полевые Core Web Vitals и нагрузочный SLA не измерялись.

## Не подтверждено этой приёмкой
Реальный новый токен/Chat ID, внешний SMTP и попадание во входящие, реальная доступность CAPTCHA для посетителей РФ, банковский счёт/СБП/чек, настройки Nginx/CDN/firewall, удалённая Turso, Windows/macOS/Safari, полное соответствие WCAG и законодательства. Полного независимого security-аудита не было.
