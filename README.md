# SOLVAR

**Актуальная техническая проверка:** [TECHNICAL-FIXES.md](TECHNICAL-FIXES.md).

**Запуск на Windows:** [WINDOWS-START.md](WINDOWS-START.md).

Премиальная витрина сигар, табака и аксессуаров в строгом минимализме: чёрный, графитовый, слоновая кость и приглушённый металлический акцент.

## Стек

- React 19 + Vite 7 + Tailwind CSS 4 — клиентская витрина и панель управления.
- Bun + Hono + oRPC — сервер и типизированный API.
- Drizzle + libSQL — локальная SQLite или Turso.
- Better Auth — закрытый вход администратора.
- Серверная обработка заявок, защита от повторов, CAPTCHA и уведомления по Telegram/email — настраиваются отдельно.

## Локальный запуск

Требуются Node.js 22.12+ и npm 10+. В корне проекта:

```sh
npm ci
cp .env.template .env
```

На Windows CMD используйте `copy .env.template .env`; в PowerShell — `Copy-Item .env.template .env`.

В `.env` задайте `BETTER_AUTH_SECRET` случайной строкой не короче 32 символов, `ADMIN_EMAIL` и `ADMIN_PASSWORD` длиной от 12 символов. Для локального запуска оставьте `WEBSITE_URL=http://localhost:4200` и `DATABASE_URL=file:./local.db`.

```sh
npm run db:push
npm run db:seed
npm run dev
```

Витрина откроется на `http://localhost:4200`, админка — `/admin`. Стартовые карточки специально неактивны: они не появятся посетителям, пока администратор не внесёт реальные названия, цены, характеристики и фотографии и не включит отображение.

## Важно при обновлении старой базы

Новая версия использует разделы `cigars`, `tobacco`, `accessories`, `sets`. Если вы подключаете базу старого проекта, **не запускайте новый сервер сразу**: старые записи каталога несовместимы с новой схемой разделов.

1. Сделайте отдельную резервную копию файла SQLite или убедитесь, что есть резервная копия Turso.
2. Настройте `.env` на эту базу и выполните `SOLVAR_MIGRATE_CATALOG=YES npm run db:migrate:solvar` (в PowerShell задайте переменную через `$env:SOLVAR_MIGRATE_CATALOG="YES"`).
3. Скрипт сохранит JSON старых товаров и настроек в папку `backups/`, заменит каталог четырьмя скрытыми шаблонами SOLVAR и обновит брендовые тексты. Записи заказов, история заказов и интеграционные настройки не удаляются. После миграции проверьте юридические страницы, контакты и работу админки.

Без точного значения `SOLVAR_MIGRATE_CATALOG=YES` миграция откажется вносить изменения. Архив каталога не включается в Git.

## Админка

`/admin` → вход через `ADMIN_EMAIL` и пароль, заданные до первого запуска `db:seed`. Публичная регистрация отключена. Администратор может добавлять, редактировать и скрывать товары, задавать стоимость и изображения, настраивать тексты и контакты, а также обрабатывать заявки при отдельно активированном приёме.

## Заказы и интеграции

По умолчанию приём заявок выключен. Онлайн-эквайринг в проекте не подключён: заявка — не оплата. Для включения приёма требуется настройка каналов уведомлений, CAPTCHA в production, документов и реальных условий продажи. Не включайте эту функцию до проверки требований страны, в которой работает магазин.

Экран 18+ — это только подтверждение посетителя в текущей сессии. Он **не заменяет проверку документов или иной юридически требуемый способ подтверждения возраста**. До запуска отдельно проверьте местные правила продажи табачной продукции, дистанционной торговли, рекламы, доставки и обработки персональных данных. Правовые тексты, контакты, ИНН/регистрационные сведения и условия доставки в шаблоне не являются готовой юридической документацией.

## Проверки

```sh
npm run build:web
npm run typecheck
npm run build
```

Серверные тесты заказов используют только отдельную тестовую базу `orders-v2-test`, локальный SMTP-мок и имитации Telegram/CAPTCHA. Не направляйте тестовые сценарии на production-базу. Результаты проверки текущей переделки и ограничения тестовой среды описаны в `TECHNICAL-FIXES.md`. Тесты исходного проекта не следует считать проверкой текущего дизайна и каталога.

## Перед публикацией

- Выберите реальный домен и укажите его в `WEBSITE_URL` и настройках веб-сервера.
- Заполните каталог подтверждёнными товарами, ценами и фотографиями.
- Проверьте документы, ограничения на рекламу и способы проверки возраста в юрисдикции продаж.
- Настройте резервное копирование БД, HTTPS, доступ к серверу, SMTP, Telegram и CAPTCHA.
- Проверьте карточки товаров и заказ на реальном staging-окружении; ключи и секреты не храните в репозитории.
