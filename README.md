# SOLVAR

Веб-приложение каталога SOLVAR с административной панелью, страницами категорий и товаров, управлением контентом и записью на посещение магазина.

## Технологии

- React, Vite и Tailwind CSS — пользовательский интерфейс.
- Bun, Hono и oRPC — сервер и API.
- Drizzle ORM и libSQL — хранение данных.
- Better Auth — аутентификация административной панели.

## Требования

- Node.js 22.12 или новее.
- Bun 1.3.14.

## Локальная настройка

В корневой папке проекта выполните:

```sh
bun install --frozen-lockfile
node tools/setup-local-env.cjs
```

Скрипт создаст `.env`, если файла ещё нет. Укажите в нём `ADMIN_EMAIL` и `ADMIN_PASSWORD` (не менее 12 символов). Для локальной базы используйте `DATABASE_URL=file:./local.db` (файл создаётся в `packages/web`) и `WEBSITE_URL=http://localhost:4200`.

Инициализируйте базу и создайте начальные записи:

```sh
bun run db:push
bun run db:seed
```

Запуск веб-интерфейса для разработки:

```sh
bun run dev
```

Production: `bun run build`, затем в `packages/web` команда `bun run start` (читает `../../.env`).

## Административная панель

Откройте `/admin` и войдите с учётными данными, заданными до первого заполнения базы. Публичная регистрация администраторов отключена. Не храните `.env`, пароли и токены в репозитории или в публичном архиве.

## Каталог и резервирование

Магазин работает в обычном режиме: публичный каталог, категории (`/collections/<раздел>`), карточки (`/products/<id>`), корзина с количеством позиций и кнопка «Зарезервировать». После успешного сохранения заявки в базе клиент видит сообщение «Ожидайте обратной связи по оформлению». Оплата на сайте не принимается.

- Карточки, категории, цены и тексты редактируются в `/admin`. Карточка попадает в публичный каталог, когда включена публикация («Опубликовать в каталоге»).
- Заявки видны в `/admin` (раздел заявок), статусы: «Новая», «Связались», «Подтверждена», «Завершена», «Отменена».
- Приём заявок включается/выключается владельцем в настройках интеграции в админке. После `db:seed` он включён.
- Уведомление менеджеру приходит в Telegram и/или на почту, если заданы `TELEGRAM_BOT_TOKEN` + chat id или `SMTP_*`. Без них заявки всё равно сохраняются и видны в админке; сбой доставки журналируется и не удаляет заявку.
- Защита от спама: подписанная cookie устройства, honeypot-поле, лимиты по IP/телефону/устройству, повторная серверная валидация цены и наличия, идемпотентная повторная отправка. Для production включите Cloudflare Turnstile: `ORDER_CAPTCHA_REQUIRED=true`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`. Если капча обязательна, а ключей нет, приём заявок остаётся закрытым (в `NODE_ENV=production` капча обязательна, пока не задано `ORDER_CAPTCHA_REQUIRED=false`).
- Перед публикацией заполните реальные реквизиты, политику обработки данных, оферту и условия доставки в настройках. Соответствие законодательству страны продаж (в том числе правилам оборота и рекламы табачной продукции) остаётся ответственностью владельца.

## SEO

Для каждой страницы формируются уникальные title/description (для карточек можно задать свои в админке), canonical, Open Graph, хлебные крошки с разметкой `BreadcrumbList`, `Product` для карточек. `robots.txt` закрывает `/admin`, `/api/`; `/sitemap.xml` строится динамически из опубликованных карточек и непустых категорий (карточки с `noindex` в него не попадают). Несуществующие адреса отдают 404, адреса со слэшем на конце и `/catalog` перенаправляются на единый URL.

## Проверки

```sh
bun run typecheck
bun run build
npm run test:technical   # unit/статические проверки
npm run test:visits      # форма записи на посещение, права менеджеров
npm run test:hardening   # безопасность, миграции, резервные копии
npm run test:store       # каталог, SEO, резервирование, заявки в админке, уведомления
```

Тесты используют одноразовую БД и моки Telegram/CAPTCHA. Реальная доставка во внешние сервисы ими не проверяется.

Перед развёртыванием проверьте домен и HTTPS (`WEBSITE_URL`), абсолютный путь к базе, резервное копирование, почту и уведомления.
