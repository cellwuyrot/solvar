# SOLVAR — запуск и проверка на Windows

Для новой локальной копии: Windows 10/11 x64, Node.js 24 LTS с npm, PowerShell.
Нативный запуск Windows в среде разработки недоступен. Проверены Windows/POSIX-пути, сервер и Chromium в Linux; это не тест настоящего Windows-компьютера.

## 1. Установка

Распакуйте архив. В PowerShell перейдите в папку `solvar-store`, содержащую package.json:

```powershell
Set-Location 'C:\Projects\solvar-store'
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run env:local
notepad.exe .env
```

Замените путь своим. `npm.cmd` обходит ограничение на npm.ps1 без изменения ExecutionPolicy.
Не используйте `--ignore-scripts`: npm устанавливает исполняемый Bun 1.3.14 через postinstall.
Генератор создаёт случайный секрет только в НОВОМ `.env`, существующий файл не перезаписывает.

В `.env` заполните свои локальные `ADMIN_EMAIL` и `ADMIN_PASSWORD` длиной 12–128 символов.
Оставьте созданный `BETTER_AUTH_SECRET`, `NODE_ENV=development`, `WEBSITE_URL=http://localhost:4200`,
`DATABASE_URL=file:./local.db`, `NOTIFICATION_WORKER_ENABLED=false`.
Не добавляйте боевые доступы в локальное тестовое окружение. Сохраните и закройте редактор перед следующим шагом.

## 2. Новая база

ВНИМАНИЕ: следующие команды предназначены ТОЛЬКО для НОВОЙ локальной базы.

```powershell
npm.cmd run db:push --workspace=@template/web
npm.cmd run db:seed
```

База `local.db` будет находиться в `packages\web`, поскольку команды выполняются из workspace.
Seed добавляет четыре скрытых шаблона, настройки и владельца; не содержит реальных товаров/цен/реквизитов.
Существующий пароль не меняется от редактирования ADMIN_PASSWORD. Не удаляйте существующую базу ради сброса пароля.

## 3. Проверка

```powershell
npm.cmd run test:technical
npm.cmd run test:hardening
npm.cmd run typecheck
npm.cmd run build --workspace=@template/web
```

Ожидается 33 технических теста, успешные изолированные серверные проверки, типизация и сборка web.
`test:hardening` и `test:orders` сами создают временную базу и локальный SMTP-мок; не читают настроенную рабочую БД.
Это НЕ проверка реальных Telegram, Trioz SMTP, CAPTCHA или доставки во входящие.
Общий `npm audit` содержит нерешённые замечания monorepo; актуальное разделение — HARDENING-REPORT.md.

## 4. Запуск

Режим разработки:

```powershell
npm.cmd run dev:web
```

Откройте `http://localhost:4200/` и `http://localhost:4200/admin`.
Используйте именно localhost, соответствующий WEBSITE_URL. Остановка — Ctrl+C.
Публично доступен информационный режим. Старые торговые страницы и операции не активируются через админку.
Исходные тексты и компоненты сохранены; их недоступность в публичном режиме не означает удаление данных.

Для проверки собранного приложения после остановки dev:

```powershell
npm.cmd run serve:web
```

Эта команда запускает сервер Bun с корневым `.env`. `vite preview` не заменяет backend.
Не используйте development-режим как production-сервер в интернете.

## 5. Дополнительные администраторы

Войдите владельцем → раздел «Администраторы» → подтвердите свой пароль → укажите имя и email сотрудника.
Роль сотрудника — admin, не owner. Без SMTP учётная запись сохраняется, но приглашение не отправляется.
Настройка SMTP описана в SMTP-AND-ADMINS.md. После неё можно повторить приглашение.
Сотрудник задаёт личный пароль по одноразовой ссылке из письма. Ссылка действует час.
При отключении сотрудника его сессии удаляются; управление доступом недоступно обычному администратору.

## 6. Обновление существующей базы

Не запускайте `db:push`, seed или замену каталога на рабочей базе.
Сначала проверьте DATABASE_URL и BACKUP_DIR, остановите запись и сделайте отдельный snapshot:

```powershell
npm.cmd run db:backup
```

Сохраните выданный путь и manifest. Для проверки восстановления укажите свои фактические пути; целевой файл должен быть новым:

```powershell
$env:RESTORE_SOURCE = 'C:\Backups\solvar-actual-snapshot.db'
$env:RESTORE_DESTINATION = 'C:\Staging\restore-check.db'
npm.cmd run db:restore
npm.cmd run db:orders
npm.cmd run db:admins
```

Миграции аддитивные и сами создают проверенный backup локальной SQLite перед изменениями.
`db:admins` использует существующего пользователя ADMIN_EMAIL для назначения первого владельца; повторно владельца не меняет.
Восстановленный файл нужно проверить отдельным экземпляром приложения; не переключайте рабочую базу автоматически.
Для удалённой libSQL нужны резервирование и восстановление средствами её провайдера — локальный helper её не копирует.

## Если возникла ошибка

- Bun не установлен: `npm.cmd rebuild bun`, затем повторите команду.
- Порт занят: остановите свой предыдущий экземпляр Ctrl+C, не завершайте неизвестные процессы.
- `no such table` на новой базе: проверьте сохранение `.env` и шаг 2. На существующей базе используйте только проверенную процедуру миграции.
- После обновления нет доступа: выполните `db:admins` на правильной БД после backup; убедитесь, что ADMIN_EMAIL соответствует существующему владельцу.
- Неверный пароль: используйте пароль, с которым владелец был создан; изменение `.env` не меняет его в базе.
- SMTP не настроен / письмо не пришло: посмотрите SMTP-AND-ADMINS.md; «принято SMTP» не означает доставку адресату.
- После изменения `.env` перезапустите сервер. Не прикладывайте `.env`, базы или backup к сообщениям об ошибке.

## Дополнительный браузерный тест

Включён `tools/test-browser.cjs`: отдельный временный HTTPS-стенд с self-signed сертификатом, Chromium и Playwright.
Прогон выполнен в Linux. Для повторения нужны Playwright, Chromium и openssl; это не обязательные зависимости production и не часть npm ci.
Путь к установленному Playwright можно передать через SOLVAR_PLAYWRIGHT_MODULE, к Chromium — через CHROMIUM_PATH.
Нативная Windows-версия этого дополнительного стенда отдельно не проверялась.
