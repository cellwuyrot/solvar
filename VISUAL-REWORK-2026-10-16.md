# SOLVAR — визуальная переработка

## Что изменено

- Новая редакционная палитра: тёплая бумага `#F3F0E9`, чернильный текст `#252824`, бордовый акцент `#743B42`, глубокий зелёный `#29372F` в графическом блоке.
- Golos Text для интерфейса: 400/500/600/700; Literata для заголовков: 400/500. Кириллица проверена. Шрифты поставляются локально в WOFF, лицензии OFL — в `packages/web/public/fonts/`.
- Увеличены основной текст, элементы управления и зоны нажатия. Переработаны шапка, первый экран, сетка разделов, карточки, модальные окна, футер, проверка возраста и административная панель.
- Вместо имитации упаковки — авторская SVG-композиция монограммы. Плавное движение орбит, появление линий и мягкое изменение прозрачности; при `prefers-reduced-motion` анимации отключаются. Кнопка «Наверх» также учитывает эту настройку.
- Убраны лишние англоязычные подписи, повторный заголовок коллекции, технический ID в модальном окне и инструкции владельцу из предупреждения на главной. Юридические документы и содержимое настроек в базе не переписывались.
- Отсутствующее или не загрузившееся фото обозначается честной заглушкой, а не придуманным товаром.

## Исправленные дефекты

1. Ошибка каталога больше не выдаётся за пустую коллекцию: есть отдельное сообщение и повторный запрос. Во время ошибки не показывается ложное количество «0 позиций».
2. Фильтр и раскрытие списка сбрасываются при смене раздела.
3. Блокировка browser storage не обрушает сохранение корзины и чтение токена авторизации.
4. Исправлена привязка native dialog корзины: панель открывается справа.
5. Исправлены повреждённые символы в строке о доставке.
6. Поиск и мобильное меню не остаются открытыми одновременно; добавлены Escape, закрытие при переходе, `aria-expanded` и `aria-controls`.
7. В поиске заблокировано добавление отсутствующей позиции, как и в карточке.
8. Исправлены наложение значков поиска в формах, контраст входа, кнопки закрытия и статуса публикации.
9. Устранено горизонтальное переполнение мобильной административной панели: широкая таблица прокручивается в своём контейнере.
10. Контейнер больше не обнуляет вертикальные отступы Tailwind на внутренних страницах.
11. Длинные заголовки информационных страниц помещаются на мобильном экране.
12. Исправлены русские формы количества позиций и пустая строка с разделителем в характеристиках товара.
13. Убрана ненужная отложенная загрузка маленького футера.
14. Обойдена патологически долгая оптимизация Rollup на исходном графе зависимостей: `treeshake: false`, раздельные vendor chunks и прямые импорты только используемых Lucide-иконок. Это сознательный компромисс: стабильная сборка с сохранением семантики библиотек вместо зависания анализа. Версии зависимостей и исходный lock-файл сохранены. Код хранения токена отделён от клиента авторизации.

## Проверка

- `npm run build --workspace=@template/web`: проверка TypeScript и production-сборка Vite.
- Chromium: настольный экран 1440 px и мобильный 390 px. Дополнительно production-bundle проверен на ширинах 320/390/768/1440 px; его API-запросы направлялись на изолированный локальный backend, а не на боевой сервер.
- Главная, разделы, информационные страницы, отсутствие товара, поиск и мобильное меню.
- Пустая и заполненная корзина, открытие/закрытие, Escape, правая граница панели.
- Карточка и модальное окно на отдельной временной позиции, аварийная загрузка изображения.
- Вход тестового администратора и отображение панели на двух размерах экрана.
- Отключённый storage, аварийный ответ каталога, `prefers-reduced-motion`.
- Проверка кириллицы во всех шести локальных шрифтах; проверка склонений количества.
- В пройденных браузерных сценариях необработанные JavaScript-исключения не обнаружены.

Для проверки использовалась отдельная временная SQLite-база. Тестовые записи, учётная запись, пароли и база не входят в архив. Существующие данные, схема БД и серверные интеграции не изменены.

## Ограничения и важное перед публикацией

- Это не полный security-аудит и не гарантия отсутствия любых ошибок.
- `npm audit --omit=dev` всего monorepo на момент проверки: 46 замечаний (30 high, 16 moderate, 0 critical), преимущественно в цепочках Expo / React Native и PM2. Автоматические major-обновления не применялись: требуется отдельное обновление и тестирование соответствующих окружений. Результат аудита сохранён в `qa/dependency-audit.json`.
- Реальные отправки Telegram/SMTP, Turnstile с боевыми ключами, платёжные системы, production-развёртывание, Electron, iOS/Android не проверялись. Оплата и приём заявок не включались.
- В исходном проекте каталог состоит из скрытых шаблонов. Не добавлялись вымышленные реальные товары, фотографии, контакты или цены.
- Для запуска используйте существующие README и `.env.template`, свою базу и свои секреты. Для текущей базы миграция из-за дизайна не нужна. Не запускайте замену каталога ради обновления оформления.
- Для проверки сборки из корня: `npm ci`, затем `npm run build --workspace=@template/web`. Разработка — `npm run dev:web` после настройки окружения.
