# Исправление отображения окна карточки

## Область изменений

Исправлена только вёрстка всплывающей карточки и общее поведение модального окна. Импорт CSV, лимит поля `weight`, логика корзины и бронирования не изменены. Базы данных, реальные товары, учётные записи и внешние сервисы при проверках не использовались.

## Что исправлено

- Диалог ограничен размером видимой области экрана; по краям оставлены адаптивные отступы.
- Устранены две вложенные области прокрутки: прокручивается только содержимое карточки, вертикально.
- Колонки используют `minmax(0, ...)`, длинные строки переносятся и не растягивают окно по горизонтали.
- Изображения ограничены своим контейнером, сохраняют пропорции и полностью вписываются в него. Сохраняется заглушка при отсутствии или ошибке загрузки фото.
- На экранах до 800 px фото и текст располагаются друг под другом.
- Кнопка закрытия находится вне прокручиваемой части, остаётся видимой и получила контрастный цвет.
- Работает закрытие крестиком, Escape и нажатием на фон. Нажатие на содержимое не закрывает окно.
- После закрытия восстанавливаются прокрутка страницы и фокус на кнопке открытия.
- Для обычных диалогов, использующих тот же компонент Modal, максимальная высота учитывает новые отступы.

При длинном описании вертикальная прокрутка необходима: текст не обрезается и не уменьшается до нечитаемого размера. Короткая карточка на просторном экране показывается целиком.

## Результаты проверок

**53 / 53 сценария успешно завершены в Chromium.**

Проверялись размеры окна: 320×568, 390×844, 568×320, 768×1024, 800×600, 801×600, 844×390, 1024×768, 1440×900 и 640×450.

На каждом размере проверялись 5 вариантов: короткая карточка без фото, длинный текст и неразрывные строки, широкое фото 6000×2400, высокое фото 2400×6000, ошибка загрузки фото. Дополнительно проверены 3 обычных диалога на разных размерах экрана.

Проверки включали границы окна, горизонтальное переполнение, число вертикальных областей прокрутки, доступность нижнего содержимого, видимость крестика после прокрутки, закрытие тремя способами, восстановление фокуса и отсутствие исключений JavaScript. Максимальное горизонтальное переполнение карточки: **0 px**. Активных вертикальных областей прокрутки: **не более одной**.

На исходном архиве тот же тест останавливается на первом сценарии 320×568: карточка не сохраняет необходимые отступы от границ экрана. Исправленная версия проходит весь набор проверок.

Это изолированные тесты реальных компонентов ProductCard/Modal и CSS на нейтральных данных. Обращения к API каталога заменены заглушкой; попытка изменить корзину в тестах вызывает ошибку. Реальная корзина и бронирование не тестировались. Эмуляция размеров окна не заменяет проверку на физических устройствах; Safari и Firefox не проверялись.

Артефакты в `qa-detail-layout/`:

- `results.json` — измерения по сценариям;
- `test.log` — журнал 53 успешных проверок;
- `390-short.png`, `390-long.png`, `1440-short.png`, `1440-wide-image.png` — скриншоты.

## Проверка сборки

Успешно выполнено:

```sh
npm run build --workspace=@template/web
```

Команда выполняет `tsc -b && vite build`: проверка TypeScript и production-сборка прошли.

Команда верхнего уровня `npm run build:web` в тестовом окружении не смогла запустить Bun через Turbo (`Exec format error`). Поэтому веб-сборка выполнена напрямую указанной выше командой. Конфигурация менеджера пакетов проекта не менялась.

## Повторный запуск визуальных тестов

После обычной установки зависимостей проекта дополнительно потребуется Playwright:

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:detail-layout
```

Для установленного системного Chromium можно вместо загрузки браузера задать путь:

```sh
CHROMIUM_PATH=/путь/к/chromium npm run test:detail-layout
```

При необходимости поддерживается `SOLVAR_PLAYWRIGHT_MODULE` с путём к установленному модулю Playwright. Тест использует локальный HTTP-сервер на свободном порту и не запускает сервер магазина.
