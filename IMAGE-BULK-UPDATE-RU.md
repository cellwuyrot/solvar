# Массовая загрузка изображений товаров — повторная проверка (23.10.2026)

В админке вкладок «Товары» и «Наборы» доступен выбор произвольного количества изображений JPG, PNG, WebP за одну операцию. Файлы обрабатываются по очереди; количество файлов не ограничено интерфейсом. Имя файла без расширения сопоставляется с названием товара или ID, без учёта регистра и разделителей. Товар с существующим изображением не изменяется. При неоднозначном названии файл пропускается. Статус отображается счётчиками.

Изменения повторной проверки:
- Добавлена предварительная серверная проверка `checkImageByName` до обработки и передачи изображения, чтобы не загружать файлы без подходящей карточки.
- Исправлена неоднозначность: сопоставление проверяет ВСЕ товары, включая уже имеющие изображения; выбор не делается случайно среди пустых карточек.
- Исправлена нормализация имени: расширения файла удаляются явно, остальные точки в названии не трактуются как расширения.
- После обработки изображения назначаются через существующее поле `image` в `shop_products`, используемое админкой и витриной. Обновление выполняется условно только при пустом поле изображения.

На больших каталогах это увеличивает размер БД; стоит заранее проверять доступное место и делать резервную копию.

## Команды для проверки в рабочем окружении
1. Установить Bun 1.3.14, выполнить `bun install` в корне.
2. Настроить `.env` на основании `.env.template`, подготовить БД по `README.md` / `DEPLOYMENT-RUNBOOK.md`.
3. Выполнить `bun run build:web` и `bun run dev:web`.
4. Авторизоваться в админке, создать тестовый товар без фото, загрузить одноимённый JPG и убедиться, что картинка видна в карточке админки и на витрине после обновления страницы.
5. Проверить повторную загрузку (не перезаписывает), неизвестное название (пропуск), одноимённые товары (неоднозначно).
